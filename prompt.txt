# AGENTFI — COMPLETE END-TO-END PROJECT BUILD SPECIFICATION

## 0. ROLE

You are a senior staff-level full-stack engineer, AI-agent architect, Web3 engineer, security engineer, DevOps engineer, and product designer.

Your task is to build a production-quality hackathon MVP called:

# AGENTFI

### Tagline

**"Your AI agent economy, directly in WhatsApp."**

AgentFi is a WhatsApp-native AI-agent marketplace where users can:

1. Create an account without installing MetaMask.
2. Receive an embedded wallet automatically.
3. Discover AI agents.
4. Purchase or subscribe to individual agents.
5. Purchase pre-built agent packs.
6. Compose multiple agents into a strategy.
7. Give agents limited and revocable permissions.
8. Ask agents to research financial markets.
9. Receive market opportunities through WhatsApp.
10. Let agents collaborate with one another.
11. Allow agents to discover and pay other specialized agents/services.
12. Execute simulated/testnet trades through Uniswap.
13. Track portfolio performance.
14. Rate and review agents.
15. View agent reputation and performance.
16. Pay developers using stablecoins.
17. Use onchain identity and reputation infrastructure.

The product must feel like:

> **WhatsApp + App Store + AI Agents + Web3 Wallet + Agent Economy**

The user should NOT need to understand Web3.

---

# 1. PRIMARY PRODUCT VISION

The fundamental principle is:

> **Web3 should be infrastructure, not user experience.**

The user should not have to:

* Install MetaMask.
* Understand seed phrases.
* Understand gas.
* Copy wallet addresses.
* Switch networks manually.
* Understand smart contracts.
* Understand blockchain terminology.

The user should be able to simply use WhatsApp.

Example:

USER:

"I have $100. I want medium-risk crypto opportunities."

"Got it. Your profile is:

Daily loss limit: $10

I found an agent pack that matches your preferences.

Balanced Alpha Pack

* NewsScout
* MarketMind
* WhaleWatcher
* RiskGuardian

$5/month

Activate?"

USER:

"Yes."

AgentFi:

"Activated."

The rest happens in the background.

# 40. SECURITY REQUIREMENTS

Never:

* Put private keys in environment variables if avoidable.
* Give LLM unrestricted wallet access.
* Allow arbitrary transaction execution.
* Allow agent withdrawal permissions.
* Trust LLM output directly.
* Allow an agent to modify its own permissions.
* Allow agents to bypass RiskGuardian.
* Allow user funds to be accessed outside defined policies.

Use:

* Permission engine
* Transaction simulator
* Spending limits
* Allowlisted contracts
* Allowlisted assets
* Expiring permissions
* Human approval
* Secure key management
* Audit logs
